<objective>
Establish the new Onshape bounding-box API surface and de-risk this phase's single
biggest unknown — the bounding-box coordinate frame — BEFORE any check/enrichment
code is written. Adds two typed client methods (per-part `getBoundingBoxes` for the
perimeter hull, assembly-level `getAssemblyBoundingBoxes` for whole-robot height),
ships a throwaway live-verification spike that resolves RESEARCH Assumptions A1–A4,
and flips the four now-Game-Manual-verified season limits from PLACEHOLDER to VERIFIED.

Purpose: The per-part endpoint is inferred (not documented) to return Part-Studio-LOCAL
coordinates needing `Fact.transform` applied, while the assembly-level endpoint is
inferred to be already world-space. Getting this wrong double-transforms every hull
point (03-RESEARCH.md Pitfall 1) — so a live spike must confirm it first, exactly as
Phase 2's `spike-mass-properties.ts` de-risked the mass contract.
Output: Two client methods, the spike script, a recorded 03-BOUNDING-BOX-CONTRACT.md,
and a verified season config.
</objective>

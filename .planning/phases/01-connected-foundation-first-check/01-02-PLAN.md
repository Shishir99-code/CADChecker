## Phase Goal

**As a** FRC CAD lead, **I want to** have my design's parts gathered by a shared, tested traversal utility and evaluated by a pluggable check engine against versioned season rules, **so that** every current and future check reads the same facts and cites config-driven rule numbers instead of hardcoded strings.

<objective>
Build the pure, server-side "facts → verdicts" core of the Walking Skeleton with no Onshape network dependency: the versioned zod-validated season config, the shared occurrence-traversal utility (assembly definition → Fact[]), and the pluggable check engine registering two independent checks that both consume the same Fact[] path.

Everything here is deterministic pure-function logic — the highest-value area to test — and is developed test-first (RED → GREEN → REFACTOR). It has no dependency on OAuth or the network, so it develops in parallel with Plan 03's wiring; Plan 03 imports these exports.

Purpose: Prove the config-driven, single-facts-path check engine (Success Criterion 4 and 5) as isolated, unit-tested code before wiring it to live Onshape data.
Output: rules/2026.json, config schema + loader, Fact type, flattenAssembly, CheckEngine with two registered checks — all with vitest coverage.
</objective>
